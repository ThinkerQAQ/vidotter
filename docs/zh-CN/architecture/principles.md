# 架构原则

| 原则 | 对实现的约束 |
| --- | --- |
| 优先复用成熟组件 | FFmpeg、yt-dlp、whisper.cpp、llama.cpp 放在工具和流水线接口后，不重复实现格式处理或推理运行时 |
| 桌面任务统一管理 | Bridge 管理任务、配置和 Worker，多个界面共用功能模块 |
| 授权限定于浏览器来源 | 扩展获取页面、媒体上下文，任务快照移除凭据，重启后通过新会话恢复 |
| 本机工作区 | Web UI 使用共享资源和扩展白名单中继，HTTP 资源不内嵌 Token |
| 处理模块可替换 | 下载、封装、识别、翻译分别通过接口与可用性检查接入 |
| 移动运行时独立 | Android 复用 Go 下载代码并接入原生平台，不沿用桌面工具能力假设 |
| 工程入口统一 | `tools/vidotterdev/` 负责构建、验证、打包和部署编排，底层沿用 Gradle、FFmpeg 工具链 |

修改契约时，同时更新实现及对应参考、教程。[AGENTS.md](../../../AGENTS.md) 保留工程约定，用户操作放在文档中。代码变更应验证，并检查受影响界面流程后再宣称可用。
