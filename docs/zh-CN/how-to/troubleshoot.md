# 首次安装的故障排查

请按[新电脑首次使用教程](../tutorial/first-run-on-new-machine.md)的顺序排查。先确认浏览器与 Bridge 的连接，再检查下载器、代理或字幕模型；不要反过来处理。

## 找不到 Native Messaging host

浏览器通过名称为 `com.vidotter.bridge` 的注册项启动 Bridge，**不是**直接查找任意运行中的 vidotter 进程。

1. 在**解压后的根目录**用 PowerShell 执行 `.\bin\vidotterdev.exe install`，或在 Linux/macOS 执行 `./bin/vidotterdev install`。
2. 检查安装器是否输出了 Bridge 可执行文件路径和 `Data/native-host/` 下的 manifest 路径。
3. 在 `chrome://extensions` 或 `edge://extensions` 查看 VidOtter 的扩展 ID。如果不等于 `hfjpenjlamneepmigemmmiibebpokmik`，重新执行安装命令并加上 `--extension-id 实际的32位ID`。
4. 在浏览器的扩展页点击「重新加载」。如果后来移动过程序目录，必须在新目录重新安装。

## 环境状态一直显示 Checking environment

先通过浏览器工具栏的扩展图标启动，而不是直接输入 Web UI 地址。扩展会按需拉起 Bridge。在「设置 → 连接与运行环境」刷新健康状态。

Bridge 启动后，可以从**本机**检查 `http://127.0.0.1:17891/`。但本地端口能够响应，并不能证明扩展已经完成 Native Messaging 认证。不要将本地接口暴露到公网。

重装前先检查并停止旧的冲突进程，不要删除持久数据 `Data/`。日志位于 `Data/logs/`。

## 资源嗅探显示「暂无媒体资源」

- 回到原来的视频标签页，点击播放或拖动进度条。
- 确认当前检测的是正在播放的那个标签页。
- 优先找完整的 MP4、`.m3u8` 或 `.mpd`，而不是单独分片。
- DRM、特殊跨域请求或专有播放协议不保证支持。

没有检测结果只是尚未提交任务，不属于下载失败。具体看[第一次下载](../tutorial/first-download.md)。

## 任务创建了但下载失败

进入「下载任务」读取错误与失败阶段，检查 FFmpeg、媒体地址及会话是否过期、代理和下载目录写入权限。默认「不下载字幕」无需模型；本地 ASR 需要 whisper.cpp 和模型，本地翻译需要 llama.cpp 和模型。

网络超时后不要连续重复点击下载，应先确认是否已有任务，再尝试界面支持的重试或恢复操作。查看 `Data/logs/` 时注意不要分享鉴权信息或带签名的媒体 URL。

## 工作台打开了，但操作不生效

`http://127.0.0.1:17891/console/` 的授权操作依赖浏览器扩展转发，页面本身不持有 Bridge token。应从扩展的「打开工作台」进入，并检查扩展权限及连接状态；静态页面能加载不代表下载器已经接通。


## Bridge 重启后任务需要重新授权

打开原视频页面，按需登录并重新播放，再从下载任务选择“重新授权并继续”。Cookie 和识别出的敏感授权头不会跨 Bridge 重启持久化。若 URL 本身过期，重新检测资源；不要靠修改 `jobs.json` 或复制 Token 恢复。见[任务管理](manage-downloads.md)。

## 模型可执行程序存在，但字幕仍失败

程序与模型是两个依赖。确认工具详情中的模型已下载且被选中；英语专用 Whisper 模型不能当作多语言模型使用。翻译还需 llama.cpp 与翻译模型；本地识别后翻译必须明确指定视频语音，不能使用自动检测。见[字幕步骤](subtitles.md)。

## 手改 TOML 后设置恢复默认

先停止 Bridge，检查 TOML 语法和字段是否完整。加载器发现格式或配置校验错误时使用默认值，但不会覆盖错误文件。保留原文件备份，按[完整配置示例](../reference/configuration.md)修正，再启动；不要因此清空整个 `Data/`。

## 升级后仍显示旧版本

“设置 → 关于”分别显示扩展与 Bridge 版本。浏览器扩展页重新加载正确目录的扩展，运行新目录的安装器更新注册，并确认旧 Bridge 已停止。只替换 Bridge 不会刷新浏览器已加载的 HTML、JS 和语言文件。见[升级指南](upgrade.md)。

## 报告问题时附什么

提供系统与架构、浏览器、扩展/Bridge 版本、失败阶段、可复现步骤和已脱敏错误。可补充日志中的任务 ID 和对应事件；不要直接上传整个 `Data/`。任务快照可能包含来源 URL，`bridge.json` 含认证信息。说明问题发生在安装、资源检测、下载、封装还是字幕，便于定位。
