# 管理下载与恢复中断任务

在 Popup、Side Panel 或工作区打开“下载任务”，看到的是同一组 Bridge 任务。操作前先查看状态、阶段、错误和输出文件。

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `queued` | 已提交，等待 Worker 工作 | 等待；长时间停留则检查运行状态 |
| `running` | 正在下载或处理 | 查看阶段，必要时暂停 |
| `paused` | 已停止，保留可恢复状态 | 来源仍可访问时继续 |
| `needs-session` | 恢复的任务需要重新获取浏览器授权 | 打开原页面，重新授权并继续 |
| `failed` | 下载或处理阶段失败 | 修复错误原因，再重试 |
| `completed` | Worker 已完成 | 打开文件，检查播放和字幕 |

## 暂停、继续和重试

暂停会停止活动 Worker；继续用于暂停任务，重试用于失败任务。下载器会复用支持的检查点，但不保证所有来源、过期链接或外部工具都能恢复。

Bridge 快照会移除 Cookie 和识别出的敏感授权头。重启后，中断的公开任务恢复为暂停；需要这些凭据的任务可能进入 `needs-session`。保留或重新打开原页面，按需登录并播放，再选择“重新授权并继续”。如果媒体 URL 本身已过期，应重新检测当前资源，而不是反复重试旧 URL。

需要保留断点时，不要删除 `Data/work/`；Bridge 运行时不要手改 `jobs.json`。

## 输出与删除

通过任务的打开、定位操作或配置的下载目录检查文件。播放列表可能生成多个文件，应逐项检查。字幕阶段失败时可能已留下可用媒体，重新下载前先确认输出。

删除任务记录默认保留输出，只有明确选择删除文件才清除对应媒体。“清空”移除已完成和失败记录，不是清理磁盘的命令。选择删除文件前，先备份需要保留的媒体。

升级程序时如何保留任务和设置见[升级](upgrade.md)，持续失败见[故障排查](troubleshoot.md)。
